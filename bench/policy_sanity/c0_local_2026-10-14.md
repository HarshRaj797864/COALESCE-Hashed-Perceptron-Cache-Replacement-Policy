# C0 on the laptop: the checks before any server run (2026-10-14)

The binary implementing `c0_latency_design_2026-10-14.md`, built from the
working tree on the laptop. Nothing here is a C0 result; these are the
qualifying checks that can run locally.

## Q0 -- at latency 0 nothing changes

The C0 binary at latency 0 against the binary built just before the change
(`bin/champsim_pre_c0`, md5 40b7d99d4263; the same simulator sources as
`champsim_b3v4_69ebdcce` plus the records-only event log): canneal_4t and
barnes_4t, LRU and Hawkeye, shared and private, levels 0 and 2, 1 M + 2 M.

**16 pairs, 25,476 log lines, 0 differ**, with only the wall-clock text
"(Simulation time: ...)" removed (the lines that carry it also carry cycle
counts, which are compared). The configs `make_config.py` writes at latency 0
are byte-identical to the old script's.

(A first comparison dropped those whole lines, which would have hidden a
cycle difference; `c0_server.sh`'s Q0 was corrected to remove only the
wall-clock text.)

## Q2 -- the wait happens where it should

canneal_4t, LRU, level 2, 1 M + 2 M, latency 50 against latency 0:

| | max cycles | waits | LLC store misses finding another core | upgrades |
|---|---|---|---|---|
| shared, L = 0 | 4,442,454 | (not printed) | 1,686 | 7 |
| shared, L = 50 | 4,454,858 (+0.28%) | **1,698** | 1,692 | 6 |
| private, L = 0 | 5,758,758 | (not printed) | 0 | 0 |
| private, L = 50 | 5,758,758 (same) | **0** | 0 | 0 |

- The waits equal the store misses that find another core plus the upgrades
  in the same run (1,692 + 6), exactly.
- Runtime rises by 12,404 cycles; the serial estimate (waits per core x 50)
  is about 21,000, so some of the wait overlaps other work.
- The private regime is untouched.
- `COHERENCE INVALIDATION LATENCY (CYCLES)` and the waits lines print only
  at L > 0.
